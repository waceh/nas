# 🌐 네트워크 및 외부 접속 설정 가이드 (Super DMZ & SSL)

본 문서는 **통신사 공유기(LG U+)와 내부 공유기(ASUS)의 이중 NAT 환경**을 극복하고, **무료 DDNS, 포트포워딩 및 Let's Encrypt SSL 보안 인증서(HTTPS 🔒)**를 통해 안전하고 빠른 외부 접속 파이프라인을 구축하는 전체 실전 가이드입니다.

---

## 🏗️ 0. 네트워크 토폴로지 (이중 NAT 해소 구조)

```
[인터넷 (공인 IP)]
       │
[LG U+ 통신사 공유기] (기본 게이트웨이: 192.168.219.1)
       │ ➔ ⚡ Super DMZ 설정 (ASUS WAN MAC 주소로 모든 외부 트래픽 1:1 패스스루)
[ASUS 메인 공유기] (기본 게이트웨이: 192.168.1.1 / DDNS: your-domain.asuscomm.com)
       ├── 🖥️ Proxmox Host (192.168.1.200)
       ├── 📦 VM 101: 헤놀로지 (192.168.1.132) ➔ DSM 관리 & NFS 스토리지
       ├── 📸 LXC 103: Immich (192.168.1.103) ➔ 사진 백업 (:2283)
       ├── 🎬 LXC 105: Jellyfin (192.168.1.105) ➔ 미디어 스트리밍 (:8096)
       └── 💻 PC / Mac / 스마트폰 (192.168.1.x 유무선)
```

---

## 🚀 1. 1단계: LG U+ 공유기 Super DMZ 설정 (이중 NAT 완전 해소)

통신사 공유기가 앞단에서 외부 포트를 차단하지 않도록, ASUS 공유기로 모든 외부 트래픽을 1:1 직접 넘겨주는 **Super DMZ**를 설정합니다.

### 📋 설정 절차
1. **ASUS 공유기 WAN MAC 주소 확인**:
   - ASUS 관리자 페이지(`http://192.168.1.1`) ➔ **[네트워크 지도]** 또는 **[WAN] ➔ [인터넷 연결]**에서 `WAN MAC 주소` 확인.
2. **LG U+ 공유기 관리자 페이지 접속**:
   - 브라우저에서 `http://192.168.219.1` 접속 및 로그인 (비밀번호: 공유기 바닥 라벨 스티커).
3. **Super DMZ 활성화**:
   - **[네트워크 설정] ➔ [NAT/라우터 설정] ➔ [DMZ / Super DMZ]** 메뉴 이동.
   - **`Super DMZ`** 선택 ➔ 접속 단말 목록에서 ASUS 공유기 선택 (또는 WAN MAC 주소 직접 입력).
   - **[적용]** 클릭.

> 💡 **왜 일반 DMZ 대신 Super DMZ인가요?**  
> 일반 DMZ는 IP(`192.168.219.x`) 기반이라 공유기 재부팅 시 IP가 바뀌면 풀릴 수 있습니다. 반면 **Super DMZ는 하드웨어 고유번호(MAC 주소) 기반**이므로 공유기를 수백 번 재부팅해도 절대 풀리지 않고 공인 IP가 1:1로 직결됩니다.

---

## 🌍 2. 2단계: ASUS 공유기 무료 DDNS 및 포트포워딩 설정

ASUS 공유기가 공인 IP 트래픽을 온전히 수신하므로, 이제 **ASUS 관리자 페이지(`http://192.168.1.1`) 한 곳에서만** 모든 외부 연결을 제어합니다.

### 2-1. 무료 DDNS 등록 (고정 주소 만들기)
1. ASUS 관리자 ➔ **[WAN] ➔ [DDNS] 탭** 이동
2. 설정값:
   - **DDNS 클라이언트 활성화**: `예`
   - **서버**: `WWW.ASUS.COM`
   - **호스트 이름**: 원하는 도메인 이름 입력 (예: `your-domain` 입력 시 `your-domain.asuscomm.com` 생성)
3. **[적용]** 클릭 ➔ "Registration is successful" 확인.

---

### 2-2. 포트포워딩 (Port Forwarding) 규칙 등록
외부에서 들어온 요청을 목적지 내부 NAS/컨테이너로 연결해 줍니다.

* 위치: **[WAN] ➔ [가상 서버 / 포트 포워딩]**
* **포트 포워딩 활성화**: `예`

| 서비스명 | 외부 포트 (WAN) | 내부 IP (LAN) | 내부 포트 | 프로토콜 | 용도 및 비고 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **HTTP-80** | `80` | `192.168.1.132` | `80` | TCP | Let's Encrypt SSL 인증서 도메인 검증용 (필수) |
| **DSM-HTTP** | `5000` | `192.168.1.132` | `5000` | TCP | 헤놀로지 기본 웹 관리자 |
| **DSM-HTTPS** | `5001` | `192.168.1.132` | `5001` | TCP | 헤놀로지 보안 로그인 & 모바일 앱 (DS file/Photos) |
| **Immich** | `2283` | `192.168.1.103` | `2283` | TCP | 모바일 사진 자동 백업 |
| **Jellyfin** | `8096` | `192.168.1.105` | `8096` | TCP | 미디어 스트리밍 웹/앱 |

> 🔒 **보안 수칙**: Proxmox 관리 포트(`8006`)나 SSH(`22`) 등 중요 인프라 관리자 포트는 포트포워딩으로 외부에 열지 말고, 필요 시 **ASUS 내장 VPN (WireGuard)**을 통해 접속하는 것을 권장합니다.

---

## 🔒 3. 3단계: 헤놀로지 Let's Encrypt SSL 인증서 발급 (HTTPS 자물쇠 🔒)

외부에서 비밀번호나 파일을 전송할 때 패킷 감청을 방지하기 위해 공인 무료 SSL 인증서를 장착합니다.

### 3-1. 인증서 발급
1. 헤놀로지 DSM(`http://192.168.1.132:5000`) 접속.
2. **[제어판] ➔ [보안] ➔ [인증서] 탭 ➔ [추가]** 클릭.
3. **`새 인증서 추가`** 선택 ➔ **`Let's Encrypt에서 인증서 얻기`** 선택:
   - **기본 인증서로 설정**: `체크 (ON)`
   - **도메인 이름**: `your-domain.asuscomm.com`
   - **이메일**: 본인 이메일 주소 입력
4. **[적용]** 클릭 (80번 포트포워딩을 통해 5~10초 내 자동 발급 완료).

---

### 3-2. 서비스 매핑 및 HTTPS 강제 리다이렉션
1. **인증서 매핑**:
   - [인증서] 탭 상단 **[설정]** 버튼 클릭 ➔ '시스템 기본' 및 모든 서비스의 인증서를 `your-domain.asuscomm.com`으로 지정 후 저장.
2. **도메인 & HTTPS 리다이렉션**:
   - **[제어판] ➔ [로그인 포털]** 이동:
     - **사용자 지정된 도메인**: `your-domain.asuscomm.com`
     - **HSTS 활성화**: `체크 (ON)`
     - **자동으로 HTTP 연결을 DSM 데스크톱의 HTTPS로 리다이렉션**: `체크 (ON)`
   - **[적용]** 클릭.

---

## 🔄 5. 자동 갱신 및 유지관리 주의사항

- **인증서 90일 만료 주기**: Let's Encrypt 글로벌 표준에 따라 90일마다 만료되지만, **헤놀로지 DSM이 만료 30일 전에 알아서 백그라운드 무한 자동 갱신**합니다.
- **80번 포트 유지**: 자동 갱신 검증 통과를 위해 공유기의 **`80`번 포트포워딩 규칙은 상시 유지**해 두어야 합니다.
- **재부팅 안전성**: 모든 설정(Super DMZ, DDNS, 포트포워딩, SSL 인증서)은 하드웨어 플래시 메모리 및 시스템 디스크에 영구 저장되므로 공유기나 NAS 본체를 재부팅해도 100% 안전하게 유지됩니다.

## ⚡ 6. 3-포트 Multi-NIC 물리 분리 및 맥북 1:1 직결(Direct Link) 최종 구성

메인보드 온보드 3대 물리 랜카드(Intel I219-LM 1개 + Intel I226-V 2.5G 2개)를 가장 직관적인 0-1-2 매핑으로 분배하여 **홈네트워크 전용선**과 **토렌트/헤놀로지 전용 2.5G 브리지**, 그리고 **맥북 1:1 초고속 직결 통로**를 완성한 종결 구성입니다.

```
[1번 슬롯 (nic0)] ──▶ ASUS 공유기 선 1 ➔ vmbr0 (192.168.1.200: 메인 Proxmox, 웹 콘솔, AdGuard, Homepage)
[2번 슬롯 (nic1)] ──▶ ASUS 공유기 선 2 ➔ vmbr1 (헤놀로지 VM 101 & 토렌트/미디어 전용 2.5G 독립 브리지)
[3번 슬롯 (nic2)] ──▶ 내 맥북 Dock 선   ➔ vmbr2 (10.10.10.1: 맥북 1:1 직결 전용 통로, ~0.7ms)
────────────────────────────────────────────────────────────────────────────────────────────
[4번 슬롯 (더미)] ──▶ ❌ 비워둠 (미실장 더미 슬롯)
```

### 📋 주요 구성 요약
- **`vmbr0` (1번 슬롯 `nic0`)**: 공유기 메인 IP `192.168.1.200/24` (게이트웨이 `192.168.1.1`). Proxmox 관리 및 웹 서비스 전담.
- **`vmbr1` (2번 슬롯 `nic1`)**: 공유기 2차 라인 2.5Gbps 전용 L2 브리지. 헤놀로지 VM 및 토렌트 다운로더를 격리하여 트래픽 간섭 0%.
- **`vmbr2` (3번 슬롯 `nic2`)**: 맥북 1:1 직결 전용 브리지. IP `10.10.10.1/24` (게이트웨이 없음).
  - 맥북 유선 설정: IP `10.10.10.2`, 서브넷 `255.255.255.0` (라우터/DNS 비워둠).
  - 맥북 직결 웹 접속: `https://10.10.10.1:8006` (공유기 거치지 않는 초고속 직결 콘솔).
  - 맥북 직결 파일 공유 (헤놀로지 SMB): `smb://10.10.10.101` (1:1 다이렉트 무간섭 광속 파일 복사).
- **자동화 스크립트**: [`apply_network.sh`](../../apply_network.sh) 및 [`self-nas/scripts/setup_network_bonding_pve.sh`](../scripts/setup_network_bonding_pve.sh)
